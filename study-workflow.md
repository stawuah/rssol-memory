# Study Workflow

Use this workflow every week.

## 1. Read

- Read the weekly `README.md`
- Read the `interactive-guide.md`
- Skim the prior week retrospective before starting

## 2. Predict

Before each exercise, write down:

- what the code should do
- what state exists
- what could fail
- what the test probably expects

## 3. Implement

- solve one exercise at a time
- do not jump to the mini-project early
- do not copy a solution before you can explain the problem

## 4. Debug

For every failure, write:

- the exact compiler or test error
- what it really means
- what assumption you had that was wrong

## 5. Explain

After the fix, explain the concept at three levels:

- plain English
- ELI5
- technical precision

## 6. Generalize

Ask:

- where does this appear in Rust?
- where does this appear in Solana?
- where does this appear in distributed systems?

## 7. Build

Use the mini-project to combine the week’s ideas into one coherent artifact.

## 8. Reflect

Do not skip the retrospective.
Most skill growth comes from noticing where your mental model was weak.
